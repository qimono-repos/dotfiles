# Guix inside the container machine (foreign-distro mode)

The container machine is **Linux (Debian + systemd)**. GNU Guix runs there in
its best-supported mode: a foreign distro. Nothing about `aarch64-linux`
blocks us — unlike macOS, every package ships for the container machine's arch.

## Guest bootstrap (`~/.qimono/guix-in-container.sh`)

Generated by `scripts/gen-guix-in-container.sh` (host side) into `$HOME`
— because `$HOME` is mirrored into the machine, the file is already inside
Linux. Then, inside the machine:

```bash
container machine run qi-dev
sudo bash ~/.qimono/guix-in-container.sh
```

What it does (idempotent):

1. Requires systemd as PID 1 (real `/sbin/init`) — confirms a valid machine base.
2. `apt-get update && apt-get install -y curl git xz-utils bzip2 gzip locales` —
   prereqs `guix-install.sh` needs.
3. Downloads and runs Guix's official `guix-install.sh` as root (installs
   `/gnu/store`, build users, `/usr/local/bin/guix`, the daemon + keys).
4. `guix pull --channels=<darwin>/guix/channels.scm` (nonguix + default).
5. `guix package -m <darwin>/guix/manifests/darwin-base.scm` — your user
   profile; `~/.guix-profile` is a symlink **inside $HOME**, so on a new shell
   it resolves as long as `/gnu/store` (persisted on the machine disk) is
   intact. If a machine is ever recreated, only `guix-install.sh` + `guix pull`
   must rerun; the manifest re-applies the profile.

## Making Guix available in every shell

The stowed `~/.zshrc.d/05-guix.zsh` is OS-guarded: **only** when uname ==
Linux AND `~/.guix-profile/bin/guix` exists it sources
`~/.guix-profile/etc/profile`. On macOS (Darwin) it does nothing.

## Channels

`darwin/guix/channels.scm` mirrors `gnu-guix/config/guix/channels.scm`:
nonguix (firefox, drivers, etc.) on top of `%default-channels`, pinned with the
same introduction fingerprint. Keep both in sync when you add channels.

## Why Debian, not a Guix System image

- A Guix System image would need `/sbin/init` → shepherd wiring built by hand
  (Guix's boot uses kernel cmdline init, not `/sbin/init`). Doable, but a
  build-your-own effort — the NixOS container-machine image
  (`johejo/nixos-apple-container-machine`) proves OCI base images work, yet it
  too needed custom init wiring.
- Debian + Guix-inside is the documented, boring path; your existing manifests
  and channels apply verbatim.
- Revisit "Guix System as the machine" later if the herd wants the full GNU
  box (renders the asahi budget to `/sbin/init` effort).

## Verification

```bash
container machine run qi-dev
source ~/.guix-profile/etc/profile
guix --version
guix package -I | head
guix shell hello -- hello             # sandbox smoke
```
