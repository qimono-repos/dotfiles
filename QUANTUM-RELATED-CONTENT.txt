QUANTUM-RELATED-CONTENT
=======================

Purpose for this file
---------------------
This document is an AI/LLM-oriented summary of the work already done in this repository to make Python-based quantum programming (Qiskit, PennyLane) and .NET-based Q# development possible on a Linux host. It is intended to help another agent understand the repository without needing to inspect every file directly.

High-level conclusion
---------------------
The repository does not contain a quantum application itself. Instead, it contains a host-setup and bootstrap framework for making a Linux machine quantum-ready. In practice, this means:

- Python tooling is prepared for Qiskit and PennyLane using a Guix-first base environment plus uv-managed Python projects.
- .NET 10/Q# support is prepared by documenting and scripting the use of a host-provided .NET SDK, with shell configuration and verification steps.
- Smoke tests and install scripts exist to validate that Qiskit, PennyLane, and Q# can run after setup.

What the repository does
------------------------
1. Defines a quantum-capable machine profile
   - The main repository README explicitly identifies the Ubuntu Yoga machine pack as a Qiskit/PennyLane/Q# target.
   - The machine-specific documentation under ubuntu-len-yog-AMD64 describes a layered architecture for quantum work: Guix for base tooling, uv for Python dependencies, and a host .NET SDK for Q#.

2. Creates a Python stack for quantum frameworks
   - The script ubuntu-len-yog-AMD64/scripts/install-quantum-python.sh creates or refreshes a uv-managed workspace at a path such as $HOME/source/repos/qimono-repos/quantum-workspace.
   - It pins Python 3.12 for the project, installs uv, and adds packages including:
     - qiskit
     - qiskit-aer
     - pennylane
     - numpy
     - matplotlib
     - qdk
   - This is the central repository work for making Python quantum libraries available.

3. Creates a .NET/Q# path for Microsoft quantum tooling
   - The script ubuntu-len-yog-AMD64/scripts/install-qsharp.sh verifies that dotnet exists and lists installed SDKs.
   - It also attempts to install Microsoft.Quantum.ProjectTemplates and checks the Python qdk/qsharp integration inside the uv workspace.
   - The repo explicitly treats .NET 10 as a host dependency for Q# and documents the practical reality that a clean Guix package for dotnet is not assumed to exist on the current channel set.

4. Provides shell integration for Python and .NET
   - ubuntu-len-yog-AMD64/stow-source/shell/.zshrc.d/20-uv-python.zsh sets the quantum workspace path and configures uv/Python conventions.
   - ubuntu-len-yog-AMD64/stow-source/shell/.zshrc.d/30-dotnet-quantum.zsh points DOTNET_ROOT to /usr/lib/dotnet when present and exposes dotnet tools on PATH.
   - These files make the environment easier to use in interactive shells.

5. Adds Guix manifest support for the host environment
   - ubuntu-len-yog-AMD64/guix/manifests/quantum-host.scm defines a Guix profile that includes Python, uv, stow, git, rust, cargo, cmake, make, and openblas.
   - ubuntu-len-yog-AMD64/guix/manifests/quantum-host-rust.scm provides a lighter-weight Rust slice.
   - ubuntu-len-yog-AMD64/guix/manifests/quantum-host-native.scm adds heavier native scientific build dependencies for compiling extensions.
   - These manifests support a reproducible base environment, even though the actual quantum packages are installed via uv rather than Guix.

6. Adds smoke tests for validation
   - ubuntu-len-yog-AMD64/tests/smoke-tests/hello_qiskit.py verifies a minimal Qiskit Bell-pair circuit.
   - ubuntu-len-yog-AMD64/tests/smoke-tests/hello_pennylane.py verifies a minimal PennyLane circuit.
   - ubuntu-len-yog-AMD64/tests/smoke-tests/hello_qsharp.py verifies Q# execution through the qdk Python package.
   - ubuntu-len-yog-AMD64/tests/smoke-tests/run-all.sh runs all three checks in sequence.
   - These files are strong evidence that the repo was designed to make the stack verifiable, not just documented.

Key documents that explain the intent
------------------------------------
- ubuntu-len-yog-AMD64/docs/quantum-computing.md
  This is the main design document for the stack: Python + Qiskit/PennyLane + Q# via .NET and qdk.
  It explains the architecture, install order, recommended packages, and verification approach.

- ubuntu-len-yog-AMD64/docs/quantum-host-dotnet-rust.md
  This document explains the specific issue of making Q# work in a Guix-first world. It documents that .NET 10 is expected from host Microsoft packages, while Python quantum packages are installed with uv.

- ubuntu-len-yog-AMD64/README.md
  This file ties the repo’s machine pack to the quantum stack and shows the intended architecture in a diagram.

Important implementation details
-------------------------------
The repository uses a pragmatic split:

- Guix handles the base system-layer tooling.
- uv handles the Python package environment.
- Host .NET SDK handles Q# and the broader Microsoft quantum ecosystem.

This split is important because the repo explicitly avoids pretending that all quantum tooling should be installed through one package manager.

Representative snippets
-----------------------
The following snippets capture the essence of the repository’s approach.

Snippet A: Python quantum workspace creation
```bash
# from ubuntu-len-yog-AMD64/scripts/install-quantum-python.sh
uv python install 3.12 || true
uv python pin 3.12 || true
uv add qiskit qiskit-aer pennylane numpy matplotlib qdk
```

Snippet B: Q# / .NET verification
```bash
# from ubuntu-len-yog-AMD64/scripts/install-qsharp.sh
dotnet --list-sdks
dotnet new install Microsoft.Quantum.ProjectTemplates 2>/dev/null || true
uv add qdk
```


Repository-level interpretation
-------------------------------
If a future agent needs to answer the question "What work was done in this repository to make Python Qiskit/PennyLane and .NET 10 Q# possible?", the best summary is:

- The repo prepared a dedicated quantum host environment for a Linux machine.
- It installed and documented the required base tooling via Guix and shell integration.
- It created uv-based Python project scaffolding and package installation steps for Qiskit, PennyLane, and qdk.
- It added .NET/Q# verification and environment setup for Microsoft’s quantum tooling.
- It included smoke tests and docs so the setup could be validated and reused.

In short, this repository did the environment preparation, automation, and validation work necessary for a quantum development environment; it did not implement a quantum application itself.
